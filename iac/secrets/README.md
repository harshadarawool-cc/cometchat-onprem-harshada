# `secrets/` — all credentials for the cluster (gitignored)

Everything in here is **gitignored** except this README and the redacted `*.env.example` templates.
A fresh clone has NO secrets — you regenerate/restore them (see below), then `../deploy/deploy.sh` mounts
them into the cluster as k8s Secrets. **Never commit a real value.**

```
secrets/
├── apps/<app>/            ← per-app, self-contained: everything THAT pod mounts
│   ├── .env               the app's environment (mounted as a file or envFrom)
│   ├── .env.example       redacted template (committed) — shows every key the app needs
│   ├── config.json        (analytics / extensions / sql-consumer only) JSON config the image reads
│   ├── private.pem        (chatapi / mgmtapi) JWT signing keypair — the CANONICAL copy is chatapi's
│   ├── public.pem         (chatapi / mgmtapi) JWT public key
│   ├── jwtrsakey.pem       (websocket / moderationservice / vcb / analytics / metrics-pro / extensions) JWT public key
│   └── license.txt        (chatapi / mgmtapi) CometChat licence
├── shared/
│   └── tls/               wildcard-tls (tls.crt + tls.key) — mounted by ~everything (ingress + every pod sidecar)
└── infra/                 datastore + cluster-wide secrets
    ├── cluster-creds.yml  FRESH per-cluster datastore passwords (mysql/tidb/mongo). Generated by
    │                      `deploy.sh credgen`; feeds BOTH ansible (provisions the DBs) AND the app
    │                      secrets (sync-app-db-creds.py) — so they can never drift.
    ├── seaweedfs/         S3 access-key / secret-key / s3.json (the object-store identity)
    ├── etherpad/          document-embed DB password + settings.json
    ├── region_secret      the onprem region hash (regions.hash) the mgmt image expects
    └── cc-cluster-1-ca.crt  legacy CA (kept for reference)
```

## How these become live k8s Secrets
`deploy.sh secrets` (phase_secrets):
1. `credgen` (earlier phase) writes `infra/cluster-creds.yml` — 6 fresh datastore passwords.
2. `sync-app-db-creds.py` stamps those passwords into each `apps/<app>/.env` + `config.json`
   (DB_PASSWORD by datastore, MONGO_URI by user) — so apps auth with what ansible provisioned.
3. `secrets-from-rendered.py` creates every `<app>-env` / `*-config` k8s Secret from `apps/<app>/`.
4. jwt-keys / jwt-public (from chatapi's pems), cc-license (chatapi's license.txt), wildcard-tls
   (shared/tls) are created directly.

## Restoring on a fresh clone
- `apps/<app>/.env` + `config.json`: restore from your secret store (or a `secret-pull` from a live cluster).
- `infra/cluster-creds.yml`: **don't restore** — let `deploy.sh credgen` generate fresh ones (rotation).
- `shared/tls`, jwt pems, `license.txt`: `deploy.sh secrets` self-generates the self-signed TLS + JWT keypair
  if absent; the licence must be supplied (or set `LICENCE_FILE` in `deploy/customer.conf`).
- `infra/region_secret`, `infra/seaweedfs`: restore from your secret store or let the relevant phase generate.

To **rotate** all datastore creds: delete `infra/cluster-creds.yml`, then re-run `datastores` + `secrets`.
